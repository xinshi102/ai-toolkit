# Codex Plan Map

本机计划导图适配器：持久保存计划，显示当前步骤、完成/阻塞状态与进度，支持节点详情、折叠、缩放、修改状态及改父子分支。用户可直接编辑，AI 通过 MCP 工具更新；以保存的版本号防止相互覆盖。

## 当前安装

本机已通过 `codex mcp add plan-map -- .../node .../server.js` 注册启用，技能在 `~/.codex/skills/plan-map/SKILL.md`。当前对话的工具清单不会因注册命令自动改变；新对话/刷新宿主后应检查 plan-map 工具是否出现。

四个工具：`plan_list`、`plan_import`、`plan_node`、`plan_view`。导入使用稳定 planId；重开对话先读取旧计划。现有计划任何改动都需要最新 expectedRevision；发生冲突重新读取，不盲目覆盖。最多 200 个节点。

MCP App 资源为 `ui://xinshi-plan-map/v6.html`，遵循 MCP Apps UI bridge，只有 plan_view 关联 UI。默认仅在对话内显示 MCP App，不为验证显示而自动打开右侧浏览器。无法确认内嵌显示时应报告限制；只有用户明确要求浏览器版时才打开 plan_view 返回的 viewerUrl。用户截图已确认本机内嵌显示；新版本布局仍需宿主重连后验收。

持久数据默认在 `~/.codex/plan-map/<planId>.json`。PLAN_MAP_HOME 可设置独立位置，便于验收隔离。服务只监听 127.0.0.1，端口由系统分配；浏览器请求检查 Host、Origin 与本次进程随机令牌。不会读取聊天记录、调用模型或上传计划。计划可能含私密内容，不把数据目录提交到 GitHub。

## 使用

告诉 Codex：“用 plan-map 登记这份计划，并在执行时更新当前步骤。”然后提供计划文本。点击节点看详情和修改状态；点击分支圆点折叠，使用“适应窗口”查看全图，放大后可滚动查看。进度只统计叶子工作项，阶段状态单独显示。

当前示例使用这次任务的真实拆分，planId 为 `codex-plan-map-20261010`。它与 DSH 计划树不是自动同步的同一份存储；跨宿主可以使用同一导入大纲，但没有偷偷读取或修改 DSH 会话。

## 开发与验证

在本目录安装 npm 依赖后，`npm test` 运行存储与真实 MCP 协议验收。`node server.js --web` 启动独立本地预览并输出 URL。PLAN_MAP_PORT 可固定开发预览端口，常规 MCP 不需要。原有 DSH 的计划解析与布局作为本目录快照复用，未修改正在使用的 DSH Plan Map。

附带的 plugin.json/mcp.json 是分发包描述；当前本机通过明确绝对路径注册 MCP 并安装技能，不依赖插件目录缓存。跨电脑应安装依赖并在目标机注册命令，不能以登录同一账号代替本机部署。

取消注册用 `codex mcp remove plan-map`；这不会删除保存的计划。浏览器端口生命周期跟随服务进程，服务重开后从新的 plan_view 获取 URL。

## 0.4.0：缩放适配对齐 DSH 版（不再把整棵树缩到看不清）

旧版「适宽」同时按宽和高取最小比例、且没有下限：窄面板放 26 节点计划时整树缩到 0.45×（11px 字变成约 5px），
字看不清也没有滚动可言。0.4.0 换成 DSH plan-map 的取法——**适配面板 = 滚动 + 重排，不缩字**：

- 「适宽」= `clamp(可用宽 / 内容宽, 0.7, 1)`；可读下限 0.7×，再宽就横向滚动，不再为「显示完整」牺牲字号。
- 缩放改用 `viewBox` + `preserveAspectRatio="xMidYMin meet"`，`width/height = 内容尺寸 × scale`；
  不再用 `transform: scale()` 包住内容（旧写法会把内边距一起缩放，且缩放到多少都依赖手算偏移）。
- 手动 −/＋ 步长 0.1，夹在 0.7×–2×；「全局计划」回到适宽并重置基准。
- 画布高度按缩放后内容取值，上限 280px；更高就纵向滚动，仍以 `size-changed` 上报宿主。
- 放不下时的默认视角：整树在 0.7× 下仍宽于面板，就自动折叠「深度 ≥ 1 且有子节点」的分支（根与第一层保持可见），
  折叠徽标显示 `+n`；用户手动折叠/展开过之后不再自动接管。
- 打开时把初始纵向滚动对到根节点：长计划不再一上来只看到中间分支。
- 旧界面不再缓存命中：资源升级到 `ui://xinshi-plan-map/v6.html`，v3/v4/v5 仍可读（兼容老引用）。
