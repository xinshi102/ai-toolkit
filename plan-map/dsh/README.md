# plan-map · 计划树（你的计划，不是 AI 的思考流水）

右侧边栏一张**计划树**：节点就是你给的计划内容，AI 执行时**自动**把节点标成进行中/已完成。

```
右侧边栏 → 计划树
┌──────────────────────────────────────────────────┐
│ 计划树 · 6 个节点 [已完成 2/6] [适应] − 100% ＋ [折叠] │
│                                                  │
│ ┌────────┐   ┌────────┐   ┌────────┐             │
│ │做游戏   ├───┤●策划案 ├───┤✓构思   │             │
│ └────────┘   └───┬────┘   └────────┘             │
│                  │        ┌────────┐             │
│                  └────────┤●成型   │             │
│                           └────────┘             │
│              ┌────────┐                          │
│              │写代码   │                          │
│              └────────┘                          │
│              ┌────────┐                          │
│              │测试游戏 │  ← 根在左、枝往右（思维导图）│
│              └────────┘                          │
├──────────────────────────────────────────────────┤
│ 点节点 → 这里看备注（细化内容、验收标准）             │
└──────────────────────────────────────────────────┘
```

**形式**：横向 **tidy tree**（左根右枝）。学的是现成做法：

| 做法 | 来源 | 落地 |
|---|---|---|
| 兄弟子树按边界盒依次堆叠、父节点居中于首末子节点之间、子树归一化后返回（**不重叠**） | Walker–Buchheim 线性时间 tidy tree（Reingold–Tilford 的改进版）[论文](https://dl.acm.org/doi/10.5555/1133013.1133017) | `lib/layout.js` 的 `place()` |
| **可变节点尺寸**：卡片宽度按标题实测宽度算，每列 X 取该列最宽节点 + 列间距 | non-layered tidy tree（Bruls/Huizing/van Wijk）[markmap-view 的实现说明](https://deepwiki.com/markmap/markmap/2.3-markmap-view) | `measureTitle()` / `nodeWidthOf()` / `columnX` |
| **圆角折线连接**：父右中 → 短横 → 竖 → 短横 → 子左中，拐角二次贝塞尔倒圆 | markmap / mind-elixir 一类思维导图的观感 | `elbowPath()` |
| 选中节点高亮到根的路径、其余淡出；点圆钮/双击折叠；状态色点 + 极浅底纹 | 同上 | `PlanMapBody` |

右栏又高又窄，横向布局天然纵向滚动，**深链只长宽度不长高度**（有测试锁住）。

**适配面板尺寸 = 重排而非缩字**（这是第一版最大的错）：

- **适宽（默认）**：`scale = clamp(可用宽/树宽, 0.7, 1)`——只缩到**可读下限 70%**；
  更宽就横向滚动，并在工具栏下方给出提示（「开紧凑或折叠分支」），而不是把字缩到看不清。
- **紧凑**：真正的重新排版（卡片更窄、间距更小、字号 12→11），不是缩放。
- `−`/`＋` 手动缩放限制在 0.7×–2×；`viewBox` + `preserveAspectRatio` 保证不裁切、居中。

**自适应面板**：默认「适应」——SVG 用 `viewBox` + `preserveAspectRatio`，
按面板实测尺寸（ResizeObserver）等比缩放到刚好放得下并居中；可切 100%、
用 `−`/`＋` 手动缩放（0.3×–3×），超出时容器内滚动。

**它只装你的计划**：`chain_note`（AI 的思考步骤）、工具调用流水、命令历史都不会进来。

## 节点怎么来

| 入口 | 说明 |
|---|---|
| `plan_import` 工具 | **主入口**：把整份计划一次性登记成树。接受缩进大纲或 markdown（`#` 标题 + 缩进列表），层级自动识别 |
| 批准 plan mode 计划 | 模型调 `exit_plan_mode` 时，整份计划 markdown 自动解析成树（替换语义），正文进根节点备注 |
| `plan_node` 工具 | 增量维护：加节点 / 改标题 / 移动父级 / 删除（子节点上提） |

> **实现注记（0.1.0 → 0.1.1）**：树完全从**官方事件**重建——`plan_import` / `plan_node` 的参数
> 由 harness 原样写进 `tool/call` 事件，`exit_plan_mode` 同理，`todo/write` 负责状态同步。
> 插件**不再写 `plan/node`、`plan/import` 这类自定义事件**：宿主读回会话日志时，未知事件类型
> 且没标 `ignorable` 会让**整份日志拒读**（会话从此在历史里打不开），细节见
> `docs/architecture.md` §5.1。老日志里的 `plan/node`、`plan/import` 仍被折叠，历史不丢。

> **客户端读取契约（0.1.2 踩坑）**：`projections.faceOf(key).getSnapshot()` 返回的**就是这个 key 的
> view 本身**，不是「key → view」的整张表
> （见 `dsh-api-session-controller/lib/client.js`：`getSnapshot: () => this.rows.get(key)?.value`）。
> 官方插件看起来像在读表（`projection.goal.phase`），是因为**它们自己的 view 就是 `{goal: …}` 形状**。
> 本插件的 view 是 `{nodes, progress}`，所以必须直接用返回值——曾经误写成 `snapshot["planTree"]`，
> 于是面板永远显示空态。另：Tab 还必须在 `ctx.sidebarRightTabs.register({id, kind, title, guide})`
> 登记**类型**，否则「+」/指南列表里根本看不到这个 Tab（只注册 `sidebar.right.pane.tab` 座位不够）。

`plan_import` 接受这种写法（两种混用也行）：

```
做游戏
  策划案
    构思
    成型
  写代码
  测试游戏
```

## 交互：两种方向 + 自己拖动 + 状态保存

| 能力 | 怎么做 | 状态存在哪 |
|---|---|---|
| **方向切换** | 工具栏「左右 / 上下」按钮 | `localStorage`（按会话） |
| **自由摆放（拖到哪就在哪）** | 把卡片拖到空白处松手 —— 位置被记住，自动布局不再管它 | `localStorage`（按会话的 `offsets`）；工具栏出现「自动布局」可一键清掉 |
| **拖节点改父子** | 把卡片拖到**另一张卡片上**松手 | **会话日志**：客户端发 `/planmap move <节点> <新父节点>`，宿主以官方 `command/run` 事件落库 → 投影据此改树（**不写自定义事件**，跨重启/跨设备都在） |
| **改状态** | 详情面板点「待办/进行中/完成/阻塞」 | 同上，`/planmap status <节点> <状态>` |
| **拖动平移** | 拖空白区域 | 视图位置，不持久化（方向/缩放/折叠/自由位置会记住） |
| **折叠分支** | 悬停时点卡片右侧的 `−`/`+n` 字形 | `localStorage`（按会话） |
| **选中节点** | 单击卡片（详情面板出现，可点状态）。**拖动不会选中**——拖完那次 click 会被抑制 | — |
| **改标题（就地编辑）** | **双击卡片标题** → 卡片上直接出现输入框，Enter 提交 / Esc 取消 / 失焦提交 | **会话日志**（`/planmap rename`） |
| **视图控制** | 顶栏只有「计划树 · 2/6 · ⋯」；点 `⋯` 弹出面板放：方向 / 缩放(适宽·±·紧凑) / 分支(折叠·自动布局·复位) / 信息与提示。点面板外任意处关闭 | — |

**无提示原则**（用户要求）：界面里不放说明性文案——拖动浮标、操作指引、缩放下限提示全部移除，
弹出面板只留可操作项（方向/缩放/分支）与信息（节点数/计划模式）。空计划、投影未连接、
命令报错这三类**状态/错误**文案保留（那不是提示，是事实）。

交互模型（0.1.5 修）：**拖动 ≠ 选中**。浏览器在 pointerup 之后还会补一个 click，
第一版没抑制它，于是"拖一下就弹出详情面板"、双击也被拖拽逻辑吃掉要试两次。
现在 pointerup 里记录 `suppressClick`，紧随的 click 被消费掉；双击改为**就地改标题**，
折叠只走卡片边缘的 `−`/`+n`。自检里加了这条**交互契约**（源码级断言），防止回归。

顶栏的取舍很明确：**常驻只留「标题 + 进度 + 一个 ⋯」**，其它一切（方向、缩放、紧凑、折叠、
自动布局、复位、计数、计划模式、可读下限提示）都收进弹出面板；底部详情栏也只在**选中节点**时出现，
不再有常驻的提示行。拖动时用画布底部的一个浮动小徽标提示，不占布局。

### `/planmap` 命令（客户端拖拽走的就是它，命令行也能用）

```
/planmap move <节点> <新父节点|->      # `-` 表示移到根
/planmap status <节点> <pending|active|done|blocked>
/planmap rename <节点> <新标题>
/planmap add <父节点|-> <标题>
/planmap rm <节点>
/planmap tree                          # 打印当前计划（缩进）
```

节点可以用 id **或标题**指定。命令只做校验并回执，真正的树变更由投影折叠 `command/run`
完成——所以拖拽结果和其它修改一样，从会话日志就能回放。

## 0.1.3 → 0.1.4：客户端 inject 的坑（状态切不动的原因）

客户端 `exports.inject` 里**漏了 `remote` / `remote.commands`**：cordis 的规则是「没声明就不给访问」，
于是 `ctx.remote.commands.execute(...)` 直接抛错，被我 `.catch` 吞掉 → `/planmap status` 从未发出，
会话日志里 `command/run` 事件数为 0，节点状态自然一直不变。

**已修 + 已加防**：`scripts/render-client.mjs` 现在会**按 `exports.inject` 只发放对应服务**，
并静态扫描源码里访问的 `ctx.<service>`（用反向测试确认能抓到：故意删掉声明立刻 FAIL）。
宿主侧同类问题（漏声明 `systemPrompt`）此前也是靠自检第 ⑧/⑨ 节抓的——这一类 bug 现在两侧都有闸门。

## 视觉（0.1.3 重做）

第一版每个节点左边有一条 3px 色条，又重又丑，已删掉。现在的取法是：

- **状态用前置字形**：`○` 待办 / `●` 进行中 / `✓` 完成（标题同时降不透明度）/ `!` 阻塞；
- **卡片**：1px 描边（颜色取状态色但压到 0.38–0.5 不透明度）+ 圆角 8（根节点 10 且极浅底色）；
- **hover / 选中 / 拖拽落点** 走一小段注入的 CSS（`.pm-card:hover`、`[data-selected]`、`[data-drop]`），
  而不是把交互态写死在每个元素的内联样式里；
- **连线** 1.3px 中性色，选中节点时**到根的路径**高亮成品牌色、其余分支淡出到 0.22；
- **方向可换**：`left→right`（左根右枝，横向滚动）与 `top→down`（上根下枝，适合宽而扁的面板），
  同一套 tidy tree 只换了轴。

## 节点状态怎么变（可前进、**也可回退**）

规则一句话：**谁后写谁说了算**。

- **自动**：官方 `todo_write` 每次落库都记一个时间点（`todoSeq`），插件按**归一化标题**匹配计划节点，
  把待办状态映射过来：`in_progress → 进行中`、`completed → 已完成`、`pending → 待办`。
- **显式**：`plan_node` 带 `status` 时也记一个时间点（`statusSeq`）。`id` 可以传节点 id，
  **也可以传节点标题**（`plan_node({action:"update", id:"构思", status:"done"})`）。
- 两者比较时间点：
  - 待办更新更晚 → **跟随待办**（前进：做成 → 变绿；也回退：待办改回 pending → 变回灰）；
  - 显式标记更晚 → **用显式状态**（可以 `done → active` 回退，比如发现做错了要返工）。

所以两种"回退"都成立：

| 场景 | 怎么做 | 结果 |
|---|---|---|
| AI 把待办改回未完成 | `todo_write` 里该项回到 `pending` | 节点跟着变回待办 |
| AI 直接回退节点 | `plan_node({action:"update", id:"构思", status:"active"})` | 节点变回进行中，并压过更早的待办更新 |

`blocked`（阻塞）不是特权状态，就是一个普通取值：设了会显示红色，撤了就恢复。

## 子节点：任意节点下都能加

- 任意层级（做游戏 → 策划案 → 构思 → 写设定文档 → 角色表，布局都算得出来）。
- `plan_node` 加子节点时 `parent` 可以传**父节点 id 或父节点标题**：
  `plan_node({action:"add", id:"doc", parent:"构思", title:"写设定文档"})`。
- 子节点也可以整枝迁移（`update` 改 `parent`，会拒绝成环）。
- 删除父节点时子节点**上提**一级，不丢工作项。
- 缩进大纲 import 天然支持多层嵌套（2 空格一层）；折叠显示用节点右下的 `+n` 徽标。

## 任务卡导入（与 xinshiimprove 对接）

`plan_import` 现在**直接吃 xinshiimprove 的任务卡**（`task_card_template.md` 的形状），不用先改写成大纲：

| 任务卡里的东西 | 计划树里变成 |
|---|---|
| `# 任务：<任务名>` | 根节点 |
| `## 档位 / 目标 / 预算 / 边界 / 验收方式` | 根节点备注（`档位：M ｜ 目标：… ｜ 验收方式（阶段门）：…`） |
| `## 子任务拆分` 表格的每一行 | 一个子节点（标题=子任务，备注=`产出：… ｜ 验收：…`） |
| 状态列 `待开始 / 进行中 / 已验收`（容错：`完成/done`、`wip`… ） | `pending / active / done`（`阻塞` → `blocked`） |
| 子任务状态 | 根节点状态汇总：全验收→done，有进行中或部分完成→active，否则 pending |

判定「这是不是任务卡」的规则很保守：有 `# 任务：` **且**某一节（标题含「子任务」）里真有表格行，才走任务卡解析；
其余一律仍按大纲解析（不会把普通计划误当卡片）。

实现要点：解析与「卡→节点」都在 `lib/card.js`（纯函数），execute 与投影回放共用
`parseImport()` 这一个入口——两处必须同源，否则同一次导入在 execute 与回放里会得到不同的树，重启后计划就变样了。

## ⚠️ 已知踩雷（都别再犯）

1. **不要写自定义事件类型**（0.1.x 写过 `plan/node` / `plan/import`）：宿主读回会话日志时
   未知类型且没标 `ignorable` 会让**整份日志拒读**——`session-60be894e` 就是这么坏的。
   现在整棵树都从官方事件折叠（`tool/call` 里的 `plan_node` / `plan_import` / `exit_plan_mode`；
   老日志的 `plan/node`、`plan/import` 仅只读兼容）。
2. **`inject` 里的 `systemPrompt` 不能删**：`guidance` 默认为 `true`，`apply` 会走到
   `ctx.systemPrompt.section(...)`；漏声明就是 cordis 的
   `cannot get property "systemPrompt" without inject`，而插件 apply 抛错会让
   **整个插件树加载失败**（所有插件一起消失、DSH 起不来）。
   `scripts/verify.mjs` 第 ⑧ 步用真实 loader 对拍会拦住（详见 `docs/architecture.md` §5.2）。
