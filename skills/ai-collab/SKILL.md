# AI 协作（ai-collab）

**Mac：** 已安装本机 CLI 适配器与协作窗口时，按 [Mac 决策收件箱](references/macos.md) 操作。下方是 Windows 运行器用法。

一句话：**贵的 AI 当主控，只做需求、派发、验收和汇报；便宜的 AI 当执行者，在“工作包”里自己读代码、改、测、修，直到达到验收标准。** 本目录下 `runtime/` 是运行器和看板，路径都相对本技能目录。

## 1. 什么时候用
- 用：任务大、需要多轮写代码和测试，主控额度紧张；或者要多个 AI 并行做互不重叠的部分。
- 不用：一两步能做完的小事，主控自己做；宿主自带的子 agent 就够用时，也不必进运行器。

## 2. 谁来做
- 用户的分工指令优先，例如“DSH 写代码，你只做关键工作”。
- 默认：额度充足的渠道写代码、测试、修复；稀缺渠道（当前主控）只做需求、派发、关键审查、对用户汇报。
- 续做沿用原执行者和原会话；换人或开新会话要写一句理由。

## 3. 打工作包
- **一个工作包 = 一个用户看得见的里程碑**（例如“统一入口上线”），不是一个动作。
- 写清：目标、非目标、权限边界、验收标准、交付位置。不写过程步骤，不限字数。格式见 `references/work-package.md`，样例见 `examples/spec.json`。
- 执行者默认用便宜模型（DSH 默认 `deepseek-v4.1-flash`）。确需更强模型时，在 spec 写 `model` 和 `model_reason`，并在汇报里说明。
- 验收标准里默认包含：写好里程碑笔记 `journal/<里程碑>.md`（做了什么、为什么、技术概念一两句解释、证据路径）；会写数据的包先留回滚点。

## 4. 派发与等待（最重要）
- 单个包：`python -X utf8 <技能目录>/runtime/run_package.py <包目录>/spec.json`
- 多个包、有依赖：`runtime/workflow.py init/run`（见 `references/workflow.md`，样例 `examples/graph.json`）。
- 派出后**阻塞等待**这条命令返回，只读最后一行 JSON 和 `reply.md`。**禁止 sleep 循环加读日志**：主控每醒来一次，就要重新读一遍整个上下文，额度会被这样烧光。
- 防失控在本地做，不花模型额度：同一命令同样报错连续 5 次、20 分钟没有进展、超过 2 小时，任一命中就停进程，回执里写明原因。轮数（默认 300）只是兜底，碰到时同一会话自动续，最多 3 次。
- 卡住时，主控判断是换方法、换模型还是找用户。**不要把剩下的工作拆成更小的包**。

## 5. 验收（按风险分级，默认不亲自复跑）
| 级别 | 适用 | 主控做什么 |
|---|---|---|
| L1 | 页面、样式、文案、小功能 | 看执行者给的截图/测试输出 |
| L2 | 默认 | 看证据，再自己抽检 1 项关键结果 |
| L3 | 生产数据写入、隐私/权限、不可逆操作、部署 | 独立复跑关键检查；写代码的不写自己的验收 |

验收不过：把具体问题退回给原执行者，主控不接过实现。失败记录保留，不改成通过。

## 6. 秘书模式：什么时候停下找用户
- 里程碑自验通过，就在同一轮直接派下一个。等待期间不在聊天里发“仍在等待”。
- 只在四种情况停：不可逆或超授权的操作（生产写入/重启/部署）、真实的访问阻塞、需要业务取舍、同一原因失败两次且没有新证据。
- 停的时候用固定格式，用户回一个字母即可：
  ```
  【需要你决定】一句话说明是什么事
  背景：技术背景和证据路径（几行）
  A. …（后果）   B. …（后果）
  建议：A，因为…   回复 A / B 即可
  ```
- 大阶段整体完成时，主动汇报一条：完成了什么、笔记和证据在哪、上线还需要用户确认什么。

## 7. 并行与资源
- 同一文件同一时间只能有一个执行者；目录和它的子目录算重叠范围。
- 工作树隔离不了端口、数据库、桌面程序实例，这些要么独占时段，要么另开实例。
- 只停能证明属于本任务的进程；停不掉时记为 unknown，保留资源锁。
- 跨宿主交接、取消与恢复见 `references/coordination.md`。

## 8. 看板
- 启动：`powershell -File <技能目录>/start-dashboard.ps1`，然后打开 <http://127.0.0.1:18765/>。
- 首屏回答三个问题：有没有事要我处理 → 任务做到哪了 → AI 额度和用量。点开详情能看到每个包的目标、最近 15 步动作（每 10 秒刷新）、回复和证据文件；任务可以归档。
- 看板只读。它显示通过本技能派出的包，以及 Plan Map / STATE.md 里的进度；宿主在对话里自己做的事不在看板上。详见 `references/dashboard.md`。

## 9. 状态文件
- 项目 `STATE.md` 只写“当前任务 / 下一步 / 挂起项”，不超过 40 行；历史移到 `STATE-history.md`。
- 主对话上下文明显变重时，开**空白**新对话（不要分叉），第一句只让它读 STATE.md 接续。
- 特定场景（部署、自动停止机制、Windows 写文件、界面类任务、跨渠道成本对比）开工前，读 `references/pitfalls.md` 对应小节。
