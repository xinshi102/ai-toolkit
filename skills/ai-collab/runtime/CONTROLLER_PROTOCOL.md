# 主控台 → 主控：决定交接协议（车道 ctl）

主控（GPT 等）推进长任务时，用户不再在主控台上直接续做执行者；主控台
只把决定**记下来**交给主控，避免两边同时指挥同一个执行者。

## 主控要做什么
1. 收件箱只显示主控上报的事：`NEEDS_DECISION*.md`（decide 卡片）与 Plan Map
   顶层 done 里程碑（ms 卡片）；受控包的包级 fail/done 不显示。
2. 用户在主控台点选项或写原话，等同于在聊天里回答主控。
3. 在每个检查点（派下一个包之前、写里程碑笔记之前）读
   `<task_dir>/USER_DECISIONS.md`，执行「状态：待主控处理」的条目。
4. 执行后把状态改成「已处理：<一句话>」，如 `已处理：按 A 做拖拽，已重派`。
5. `~/.ai-collab/decisions.jsonl` 是同一批决定的机器副本（status=pending）；
   标题栏「N 条决定等主控处理」来自 pending 计数。

## 格式（USER_DECISIONS.md 追加段）
```
## <ISO 时间> · <事项标题>
- 事项：<id>（<kind>）· 包：<包目录相对路径>
- 用户选择：<A 做拖拽> / 用户原话：<text>
- 状态：待主控处理
```

## 边界
- 没有主控在管的包照旧直接续做，本协议不适用。
- `decision_queued` 事件只表示「已排队」，不代表主控已处理。
- 本文件由车道 ctl 维护；xinshi 技能正本另行维护。
