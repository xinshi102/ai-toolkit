# AI 协作

服务于信使的执行层。先按信使判断是否需要跨宿主；使用当前用户授权，不因登录或技能安装扩大权限。

- 在本仓库中读取 `../../collaboration/macos/README.md`（Mac）或 `../../collaboration/windows/README.md`（Windows），确认当前已验收的适配器和命令。独立安装时先定位正本；缺组件就报告具体缺口。
- 派发前给出目标、工作目录、允许写入范围、输入与验收条件。模型只接收任务所需资料；不读取、显示或复制凭据，使用原生登录或仅在作用域进程加载用户指定环境变量。
- OpenCode、DSH、Kimi 分别核实实际入口。Kimi 桌面控制能力不等于 Kimi 模型/API，桌面聊天回执也不等于文件工具验收。
- 区分登录登记、模型响应、工具执行、产物验收。保留失败尝试；不能确认停止时保留 unknown。最终验收由主控完成。
- 需要依赖、并行写入与恢复时使用已验证工作流；普通单次协作不另建后台服务或重复任务库。不要自行启动账号登录、付费升级、公开发布或无上限重试。

## 本机命令行协作与成本分工

用户明确要求以 Codex 为入口、DSH Flash 与 OpenCode 为主要执行者。这个成本偏好优先于通用的“能用原生子agent就不跨宿主”默认方法。

- Codex：维护总计划、分解任务、决定接口、派发、集成与最终验收；不把自己能做当成必须亲自做。
- OpenCode：简单、重复、边界清楚且可独立验证的脚本/格式转换/批处理，优先使用已实测的免费模型 `opencode/deepseek-v4.1-flash-free`。免费路由限速或失败就保留证据并调整顺序，不自动切付费模型或无限重试。
- DSH：较难的独立实现、调试与复核，使用显式选定的 `deepseek-official/deepseek-flash`。仍由 Codex 核对产物；不依赖未经确认的 profile 默认模型。
- Kimi：不进入默认任务池，保留有限月额度；用户点名时再核实其命令行入口。
- 使用原生 CLI 或已验证的命令行适配器派发、接续与收件。不要用 computer use 操作其他 AI 聊天界面。CLI 不可用时报告具体缺口，不悄悄回退桌面自动化。

命令行入口、任务日志与总计划绑定见 `../../collaboration/macos/CLI-COLLABORATION.md`。派发前记录真实 argv、工作目录、公共任务包；返回后保留原生响应、工具事件、失败尝试与独立验收。不能记录凭据值或整份环境。

总计划只有一个权威来源：主控使用的 Plan Map。协作台读取同一 planId 的同一份持久文件，不复制成独立可编辑计划。每次委派绑定 planId/nodeId/runId；大型分支可有子计划但须挂回总节点，小脚本不强制另建计划。执行者完成只更新为待验收；主控核对后再更新总计划，修改遵守最新revision。


## Mac 决策收件箱（Windows ai-collab 主控台能力的本机适配）

- 对已有真实 DSH CLI 会话的公开或合成任务，主控可用 `collaboration/macos/decision_cli.py open` 提出选择；现有协作窗「总览 → 需要你决定」显示当前登记计划的事项。回答只落盘，不自动启动执行者。
- 主控先用 `list/show` 核对决定与授权，再用 `resume` 领取一次并沿用原 DSH 会话和工作目录。新尝试有独立简报、产物和回执。未确认停止不重派；收集失败但有完整原生回执时用 `recover-artifact` 恢复证据。
- 独立核对回执和产物，调用协调器 `accept` 后再 `close`。部署缺失、非 DSH 会话或不适合公开/合成派发的任务继续在聊天里接力。命令见 Mac 的 CLI 协作说明。
