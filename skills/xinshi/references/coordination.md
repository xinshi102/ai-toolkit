# 协作运行边界

版本：3.0.0-trial.2。仅在并行写入、多个执行对话或跨 harness 协作时读。

## 派发之前

给执行者最小而充分的任务包：稳定标识、目标、输入版本、工作目录、允许修改范围、接口、预期交付与验收条件。足够让它独立开始，不让用户转述聊天。

核实实际并发、创建/消息/等待/停止能力，以及共享了哪些资源。独立上下文不等于文件或运行时隔离。

## 修改与资源归属

- 同一文件同一时间只有一个执行者；目录与其子目录算重叠范围。
- 独立修改需要各自文件状态时，优先用项目允许的隔离工作区（Git 可用 worktree）；不复制出脱离事实来源的长期分叉。
- 工作树不隔离端口、数据库、桌面/Unity/Excel 等实例——独占时段或另开实例，不能靠「另一个 agent 知道我在操作」代替协调。
- 保留已有用户和其他工作者的修改；发现未知修改先查归属，暂停冲突写入，不替别人回退。

## 状态与依赖

项目已有状态系统优先；没有时只记必要字段：id/目标/交付、owner 与修改范围、输入版本与依赖、状态与等待原因、结果位置/证据/下一动作。
输入版本变化只重做受影响分支；失败保留原记录，修复另开新尝试，不把失败改成成功。

## 跨 harness 交接

共享进度固定放在完整路径 `E:/AI-Workspace/Projects/Shared/Agent-Conventions/.work/handoff/`：

- 进度：`STATE.md`（交接前先读）
- 结论：`inbox/<harness>-<时间>.md`，并在 STATE 的「交接日志」追加一条，不整份覆盖。

文件存在只证明本地内容；对方确认回执才算接收。没有真实通道时说明缺口，不臆造桥接。

## 取消与恢复

只停能证明属于本任务的执行者或进程；无法确认停止时保留 unknown，不假装已清理。

## 宿主差异

- Codex：用原生 Plan/Goal；没有计划插件时不要伪造工具。
- DSH：可用 plan-map 与原生子 agent；宿主命令失败只影响对应分支。
- Windows：用绝对路径；写宿主自身（插件/版本/配置）时，执行者不能是被改的宿主。
