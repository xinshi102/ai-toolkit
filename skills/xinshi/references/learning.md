# 学习与沉淀

- 实施前先查复用：项目已有实现 → 知识库 → 成熟开源（核对许可证和维护状态）。
- 稳定的约束写进项目 `AGENTS.md`；当前进度写进 `STATE.md`；跨项目通用的解法写进已确认的本机经验库；未配置时先留在项目内。
- 用户纠正、同一类问题第二次出现时：属于技能的，先在 `references/pitfalls.md` 对应场景小节追加一行；属于项目的，写进项目 `AGENTS.md`。追加一行可以直接做；改规则、改结构、改章节前先问用户。
- 不维护 `events.jsonl`、提案队列、评分或每日台账。宿主自带复盘的（如宿主自带的技能复盘），沿用宿主的。
