# 协作运行边界

版本：2.0.0-trial.1。仅在并行写入、多个执行对话或跨 harness 协作时使用。

## 派发之前

主控给执行者最小而充分的任务包：稳定任务标识、目标、输入版本、工作目录、允许修改范围、接口、预期交付和验证条件。提供足够上下文让其独立开始，不让用户转述聊天。

核实实际并发限制、创建/消息/等待/停止能力，以及执行者共享哪些资源。独立上下文不等于文件或运行时隔离。

## 修改与资源归属

- 独立修改需要各自文件状态时，优先使用项目允许的隔离工作区（Git 项目可用 worktree）。同一仓库的受控 checkout 不是独立项目副本；不得复制出脱离项目事实来源的长期分叉。
- 共享目录可用于职责明确的工作。按实际文件和资源分配写入归属；同一时间同一文件由一个执行者写入。共享接口由主控协调。
- 并行执行者不各自覆盖同一份进度文件。执行结果通过宿主通信或各自结果记录交回，主控维护统一状态。
- 工作树不隔离端口、数据库、外部路径、桌面、Unity/Excel 等应用实例。为这些资源分配独立实例或安排独占时段；不能靠“另一个 agent 知道我在操作”代替协调。
- 保留已有用户和其他工作者的修改。发现未知修改时先查归属和差异，暂停冲突写入；不要清理、覆盖或替别人回退。主控可处理授权范围内含义明确的合并冲突；冲突涉及不明确的用户意图或不可逆影响时请求决定。

## 任务状态与依赖

使用项目已有状态系统；没有时只为持续任务保存必要字段：

| 字段 | 用途 |
|---|---|
| id、目标、交付 | 稳定识别工作，避免靠聊天标题猜归属 |
| owner、工作目录、修改/资源归属 | 明确谁可以改什么、在哪里执行 |
| 输入/接口版本、dependsOn | 判断真正可开始的工作及结果是否过期 |
| 状态、等待原因、解除条件 | 区分待开始、就绪、执行、等待、待验证、完成、失败、取消 |
| 结果位置、验证证据、下一动作 | 验收和跨会话恢复 |

不要为每个短任务填全部字段。复杂任务需要哪些信息，就维护哪些信息。图或网格应从同一份状态生成，避免再维护一套事实来源。

主控在执行者返回、依赖满足、验证失败、环境改变或用户调整需求时，更新状态并检查下一批就绪任务。失败先判断是否局部可恢复；重试采用与风险和预算相称的停止条件，避免固定次数机械停工或无限重复。

输入版本变化后，检查哪些已完成结果需要重验证，不无依据地全部推倒重做。取消或重派时说明受影响的任务；只停止可证明属于本任务的执行者或进程。

## 同一 harness

主控负责原生子 agent 的创建、消息、等待、异常处理和回收，向用户汇总。不要要求用户分别维护每个子 agent。

多持久对话须有可用的聊天管理通道或宿主支持。缺少能力时可优先使用原生子 agent；无法可靠自动化的长时协作，向用户说明边界，不把人工搬运包装成自动管理。

## 跨 harness

仅在跨工具工作实际必要且具备授权时使用。总协调者管理跨工具目标、接口、依赖、共享资源和整体验收；各 harness 的项目主控管理本地执行，不要求用户逐个派活。

优先使用已经验证的原生通信、CLI、API 或桥接能力。文件交接只能证明本地内容存在；必须有接收方确认才能说明对方已接收。没有真实通道时明确报告阻塞或使用可执行的单 harness 方案，不臆造桥接地址、不使用未知凭据、不启动付费外部执行。

与外部主控交接采用任务标识、项目引用、当前输入版本、边界、预期结果和回执关联。不要复制整段私密历史。区分已派发、已接收、执行中、已返回和已验收。

## 跨会话与持续运行

保存目标、已确认约束、重要决定、任务关系、证据和恢复动作。新会话核对项目与任务标识，不自动接管最近一个不相关计划。

技能文本不提供持久进程。只有在实际存在并验证了运行宿主、完成事件、状态存储、恢复和取消能力时，才能承诺无人值守调度；否则只承诺当前运行期间的协调和可恢复交接。
