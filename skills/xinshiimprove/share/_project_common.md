# 项目入口流程公共节

> **触发场景**：执行 new_project / adopt_project / standardize_legacy 任一流程时｜**不用读的情况**：非项目入口类任务｜**行数**：129

版本：v1.1
更新日期：2026-09-21
上位文件：`collaboration.md`、`governance.md`

三个项目入口流程（`new_project.md`、`adopt_project.md`、`standardize_legacy.md`）的**共有部分**集中在此，各流程只写自己的差异步骤，不重复本文件内容（`governance.md` §元规则 M5）。

---

## §入口三选一

| 手上有什么 | 走哪个 | 产出形态 |
|---|---|---|
| 什么都没有，全新开始 | `new_project.md` | **骨架版**，随后渐进补足 |
| 已有项目文件（`AGENTS.md` 或等价物），在跑 | `adopt_project.md` | 成熟版（信息已存在，直接填） |
| 只有一段旧对话记录，没有项目文件 | `standardize_legacy.md` → 完成后再走 `adopt_project.md` | 成熟版（从材料提取） |

判断依据：**有没有可映射的项目文件**。

**形态差异的理由**：全新项目开工前无从知晓目标与约束，硬问只会得到编造的答案，故先建骨架后长内容；
后两条路径的信息已存在于文件或对话中，可以一次填全。

## §档位

| 流程 | 规模档 | 干预档 | 理由 |
|---|---|---|---|
| `new_project.md` | **S** | B | 只建 ≤4 个新文件、方案唯一、无不可逆操作，阶段 1+2 合并 |
| `adopt_project.md` | M | B | 需清点现状、建映射、识别冲突，多步且有取舍 |
| `standardize_legacy.md` | M | B | 需四类提取与证据分级 |

后两者的升档条件（任一满足即升 L，并在阶段 2 输出子任务拆分表）：

- 材料超过 2000 行
- 涉及 3 个以上并行主题或 3 个以上项目
- 目标项目存在正在运行的定时任务/服务，需分批切换

对 M 档「必须建任务卡」的**统一偏离**：入口流程的任务卡由各自的流程文件充当，**不另建** `tasks/` 下的任务卡。
理由：流程已完全固定在流程文件中，无可变部分。此偏离仅适用于项目入口这一类任务。

## §方案确认门（各流程的"输出方案，等确认"步骤共用）

任何入口流程在**写第一个文件之前**，必须输出方案并停下等人类确认。

**`new_project.md`（S 档，骨架）** —— 只需复述 4 项：

1. 项目名 / 项目根目录 / SHARE_ROOT 三项必答内容
2. 一句话初始描述（第 4 问；跳过则写"未提供，留待补"）
3. 将创建的目录结构
4. 明确说明："其余内容留 `（待补：...）`，在后续工作中按渐进补足规则填上"

**`adopt_project.md` / `standardize_legacy.md`（M 档）** —— 方案至少含：

1. 现状清单（材料/文件的路径与体量）
2. 拟创建的文件清单——逐个说明为什么需要；不需要的明确写"不补"及理由
3. 拟修改的现有文件清单——应当极少；每一处都要说明理由
4. 建议的规模档与干预档，及理由
5. 未决问题清单

**未确认前不写任何文件。**

## §接线（写入口文件的「协作协议」节）

接线动作**集中在项目入口文件顶部一节**，不散落到其他位置。

**完整模板见 `agents_template.md`**（单一事实来源）：骨架版见其 §AGENTS.md — 骨架版，成熟版要求见其 §AGENTS.md — 成熟版各节要求。本文件不重复。

接线时的要点：

| 块 | 填什么 | 易错 |
|---|---|---|
| 路径变量 | SHARE_ROOT 绝对路径 + **接入基线版本** | 漏填基线版本 → 将来无法察觉协议漂移 |
| 必须先读 | 以 `ROUTER.md` 为首项 + 项目引用的技能 | 列全量 share 文件 → 上下文浪费 |
| 加载方式 | 声明"其余按 ROUTER 路由表按需读取" | 不写 → AI 仍会全量加载 |
| 文件映射 | 存量项目填实际对应关系；全新项目写"与协议模板一致" | 漏掉某个协议概念 |
| 声明偏离 | 逐条写"偏离哪条 + 怎么做 + 为什么" | 只写"有差异"不写具体条款 |
| 本项目档位 | 默认干预档 + **不可逆操作清单** | 清单留空；骨架版须保留 `（暂无，⚠️ 未确认）` 而非写"无" |
| 材料来源 | 仅旧对话标准化流程需要 | 其他流程未删除该节 |

**接线完成后**：入口文件中不得残留任何 `<...>` 占位符。
`（待补：...）` 占位**不在此列**——那是骨架版的合法状态，由渐进补足规则负责填上。

## §公共验收项

各流程的验收清单**必须包含**以下项，可在其上追加自己的专有项：

```markdown
- [ ] 入口文件含「协作协议」节，六块齐全（路径变量 / 必须先读 / 加载方式 / 文件映射 / 声明偏离 / 本项目档位）
- [ ] SHARE_ROOT 为绝对路径，且该路径下 ROUTER.md 与 collaboration.md 均实际存在
- [ ] 已记录接入基线版本（collaboration.md 的当前版本号）
- [ ] 「必须先读」以 ROUTER.md 为首项，且列出的每个技能文件均实际存在
- [ ] 「本项目已知的不可逆操作」已处理：成熟版列出或明写"确认无"；骨架版保留 `（暂无，⚠️ 未确认）` 及其两条约束
- [ ] 不含任何未替换的 <...> 占位符（`（待补：...）` 不算）
- [ ] 新增文件均经人类确认，无计划外新增
- [ ] 未写入或修改 SHARE_ROOT 下的任何文件
```

## §公共知识沉淀

各流程的最后一步统一执行两件事：

1. 按 `collaboration.md` §知识库规则 评估项目知识库是否需要更新；无需更新则在报告中声明理由
2. 若过程中发现**通用**内容（换个项目也成立），按 `new_skill.md` 提议沉淀为技能。**提议即可**，是否执行由人类决定

---

## §公共边界

以下边界对三个入口流程同时生效：

- 方案未获人类确认前，不写任何文件
- 不创建流程规定以外的文件（验收清单属规定内容，可创建）
- 不写业务逻辑代码
- 不修改 `<SHARE_ROOT>` 下的任何文件（`collaboration.md` §share 目录的写权限）
- 不删除、不改名、不移动项目中任何已有文件
- 不虚构材料中不存在的内容；拿不准写"材料未覆盖"，不补全
- **不为填满模板而编造内容**；不知道的保留 `（待补：...）`，不要猜一个写上去
