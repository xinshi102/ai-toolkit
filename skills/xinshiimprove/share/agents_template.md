本文件是 `AGENTS.md` 的**单一事实来源**。
`new_project.md`、`adopt_project.md`、`standardize_legacy.md` 三个流程一律**引用本文件**，不得各自抄一份（`governance.md` §元规则 M5）。

## 两种形态

`AGENTS.md` 有两种形态，**不是两份模板，是同一份文件的两个阶段**：

| 形态 | 何时 | 特征 |
|---|---|---|
| **骨架版** | 环境初始化时创建 | 只填 4 项已知信息，其余为待补占位 |
| **成熟版** | 随工作推进逐步长成 | 各节被实际内容填满 |

**从骨架长到成熟，靠 §渐进补足规则**，不是靠某一次集中填写。
存量项目接入与旧对话标准化**直接按成熟版填写**，不走骨架版。

占位符约定：

- `<...>`：**必填**，创建时就要替换
- `（待补：...）`：**允许暂缺**，按 §渐进补足规则 在后续工作中回填
- `⚠️ 未确认`：**危险标记**，表示"还不知道"而非"确认没有"，不得当作否定结论使用

## §渐进补足规则

**AGENTS.md 是长出来的，不是一次填出来的。**

### 触发点与动作

| 触发点 | 补哪节 | 动作 |
|---|---|---|
| 人类**首次提出需求** | 项目目标 | AI 提炼一句话，**复述等确认**后写入；已有初始描述则据实修正 |
| 人类说"别动 X""必须满足 Y""不要用 Z" | 项目特有约束 | 追加一条，注明来源（人类原话）与日期。**不需要单独确认**，下次报告中提一句 |
| AI 识别出某操作属**不可逆操作** | 不可逆操作清单 | 追加一条 + **立即提议干预档**（普通不可逆 → ≥B；涉及生产/线上 → ≥C），**等人类确认后**才继续 |
| 人类明确说"本项目没有不可逆操作" | 不可逆操作清单 | 把 `（暂无，⚠️ 未确认）` 改为 `确认无（人类确认于 YYYY-MM-DD）`，此后才允许 A 档 |
| 实际用到某项环境信息（路径、权限、版本） | 项目环境 | 就地补录，注明是**实测**还是人类告知 |
| 首次引用某个技能 | 必须先读 | 追加 `<SHARE_ROOT>/skills/<技能名>.md` |
| 首次需要提交代码 | 版本控制 | 问人类一次，写入后不再问 |
| 预算不够用 / 人类调整 | 预算 | 就地修改，在补足记录中注明原值 |

### 硬规则

1. **每次补足都要在「补足记录」表追加一行**，含日期、补了哪节、摘要、来源。这是可追溯性要求（`governance.md` M6 精神）
2. **「项目目标」的首次写入必须经人类确认**；其余节可先补后报
3. **不可逆操作的补足必须当场停下**，不得"先记下来接着干"
4. **不得把「待补」当作「无」**。遇到标记为待补的节而当前任务依赖该信息时，按 `collaboration.md` §未知处理 提问
5. 补足是**追加与修正**，不是重写。已有内容除非被证伪，否则不删

### 何时算"长成熟了"

不设硬标准。但以下情况说明骨架期结束，可按需做一次整理：

- 「项目目标」已确认，且「不可逆操作」已由人类明确表态（确认无 / 已列出）
- 「项目特有约束」已有 ≥3 条
- 文件接近 200 行软上限（见下）

### AGENTS.md 的体量约束

本文件每次对话都会被加载，是常驻成本。

- **软上限 200 行**。超出时检查是否混入了应属 `knowledge_base.md` 的系统事实
- **只放"不知道就会走错方向"的前提**；"干到那一步才需要查"的细节放知识库
- 判断方法：这条信息在**任务开始前**就必须知道吗？不是 → 移入 `knowledge_base.md`
- 「补足记录」表超过 20 行时，保留最近 10 条，更早的可删（其内容已体现在正文中）

## §AGENTS.md — 成熟版各节要求

骨架长成后，各节的填写标准。存量项目接入（`adopt_project.md`）与旧对话标准化（`standardize_legacy.md`）**直接按本节填写**，不走骨架版。

| 节 | 必填 | 要求 |
|---|---|---|
| 路径变量 | 是 | SHARE_ROOT 绝对路径 + 接入基线版本号 |
| 必须先读 | 是 | 以 `ROUTER.md` 为首项 + 项目引用的技能 |
| 加载方式 | 是 | 声明"其余按 ROUTER 路由表按需读取" |
| 文件映射 | 是 | 存量项目填实际对应关系；全新项目写"与协议模板一致" |
| 声明偏离 | 是 | 逐条"偏离哪条 + 怎么做 + 为什么"；无则写"无" |
| 本项目档位 | 是 | 默认干预档 + 不可逆操作清单（无则明写"确认无"） |
| 材料来源 | 否 | 仅旧对话标准化流程需要，其他情况删除 |
| 项目目标 | 是 | 一句话 |
| 项目特有约束 | 是 | 逐条；无则写"暂无" |
| 预算 | 是 | 至少含失败次数上限 |
| 版本控制 | 是 | git / 无 / 其他 + 提交方式 |
| 项目环境 | 是 | 操作系统、关键路径、权限 |
| 产出规则 | 是 | 照骨架版原样保留 |
| 补足记录 | 否 | 骨架期产物，成熟后可保留或清空 |
