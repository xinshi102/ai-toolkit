# 新增技能协议

> **触发场景**：已明确一条通用经验，要沉淀为技能｜**不用读的情况**：还不知道有什么值得留（读 distill.md）｜**行数**：40

版本：v1.0
更新日期：2026-09-20
上位文件：`collaboration.md`

当人类说"把这个沉淀成技能""新增技能"时，按本协议执行。
`share/` 默认只读（`collaboration.md` §share 目录的写权限），本协议只在人类当次显式下令时才可执行。

## 何时该建技能

同时满足才建：

1. 该知识**与具体项目无关**，换一个项目仍然成立
2. 已在至少一个真实任务中被验证过，不是推测
3. 不属于 `collaboration.md` 已覆盖的通用协作规则

只满足项目内复用的，写进该项目 `knowledge_base.md`，不进 `share/skills/`。

## 步骤

1. **确认边界**：向人类复述——技能名、适用场景、不适用场景、准备写入的已知坑。等确认（对应阶段 1、2）。
2. **查重**：列出 `share/skills/` 现有文件，判断是否已有同类技能。已有则改为更新该文件并升版本号，不新建。
3. **按模板写**：复制 `skill_template.md` 中的代码块，另存为 `share/skills/<技能名>.md`，填齐所有必填小节。
4. **自检**（文档产物 checklist）：
   - [ ] 所有必填小节均有实质内容，无 `<...>` 残留
   - [ ] 未重复 `collaboration.md` 的通用规则
   - [ ] "已知坑"至少一条，且含现象/原因/应对三项
   - [ ] 文件名符合命名规范（小写下划线）
   - [ ] 与现有技能无重复、无矛盾
5. **登记**：在 `README.md` 的技能清单表中新增一行；在 `CHANGELOG.md` 追加一条。
6. **报告**：按 `collaboration.md` §自评报告格式 输出自评报告，附文件路径与行数，等人类确认。

## 边界

- 不修改 `collaboration.md`、`new_project.md`、`tools/` 下任何文件
- 不把项目专属信息（具体路径、具体账号、具体业务规则）写进技能文件
- 未经人类当次下令，不写入 `share/`
