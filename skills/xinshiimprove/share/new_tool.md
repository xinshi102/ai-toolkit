# 新增工具适配协议

> **触发场景**：接入新 AI 工具｜**不用读的情况**：只想查某工具限制（读 tools/<工具名>.md）｜**行数**：60

版本：v1.0
更新日期：2026-09-20
上位文件：`collaboration.md`

当需要在一个新 AI 工具（如 Cursor、Gemini CLI、某新 IDE 插件）里执行本套协议时，按本协议新增适配文件。
`share/` 默认只读（`collaboration.md` §share 目录的写权限），本协议只在人类当次显式下令时才可执行。

## 适配文件写什么

只写**本工具与其他工具的差异**。所有工具共有的约定写在 `tools/_common.md`，协作规则写在 `collaboration.md`，一律不得在适配文件中重复抄写。

判断标准：这句话在别的工具里也成立吗？成立就不该写在这里。

## 步骤

1. **确认**：向人类复述工具名、入口文件机制、已知能力缺口。等确认。
2. **建文件**：`share/tools/<工具名>.md`，文件名全小写英文 + 下划线。
3. **按固定小节填写**（四节缺一不可）：

```markdown
# <工具名> 适配

版本：v1.0
更新日期：YYYY-MM-DD

公共约定见 ./_common.md，协作规则见 ../collaboration.md。本文件只写本工具差异。

## 入口文件
<本工具自动读取哪个文件？需不需要在项目目录放一个指向 AGENTS.md 的入口文件？文件名是什么？>

## 权限与沙箱
<写操作范围限制、审批机制、网络访问限制、被拒绝时的行为>

## 能力缺口
<本工具做不到什么：截图 / 写文件 / 执行命令 / 读本地文件 / 长任务等>

## 降级方案
<针对上面每一项缺口，collaboration.md 的对应要求如何降级执行>

## 本工具特有能力（可选）
<并行子任务、目标管理、钩子等；没有则删除本节>
```

4. **自检**（文档产物 checklist）：
   - [ ] 四个必填小节齐全，无 `<...>` 残留
   - [ ] 未重复 `_common.md` 与 `collaboration.md` 的内容
   - [ ] 「能力缺口」中每一项在「降级方案」中都有对应处理
   - [ ] 若本工具无法执行 `collaboration.md` 某条硬性要求，已在降级方案中写明替代做法
5. **登记**：在 `README.md` 工具清单表中新增一行；在 `CHANGELOG.md` 追加一条。
6. **报告**：按 `collaboration.md` §自评报告格式 输出自评报告，等人类确认。

## 边界

- 不修改 `collaboration.md`、`new_project.md`、`skills/` 下任何文件
- 不在适配文件中重新定义阶段、验收、未知处理等协作规则
- 若发现某条协议规则在多个工具下都无法执行，说明该规则本身有问题：写 `pending_question.md` 提出修改协议，不要靠适配文件绕过
