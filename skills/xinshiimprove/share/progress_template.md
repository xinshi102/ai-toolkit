# 进度文件模板

> **触发场景**：XL 档任务首次建 progress.md｜**不用读的情况**：progress.md 已存在（直接读该文件的指定三节）｜**行数**：103

版本：v1.1
更新日期：2026-09-21
上位文件：`collaboration.md`

**XL 档强制**使用 `progress.md`；L 档可选；S/M 档不用（进度记在任务卡的子任务表里即可）。

职责边界见 `collaboration.md` §知识库规则：

- `knowledge_base.md` 存「这个系统**是怎样的**」——长期、跨任务
- `progress.md` 存「这件事**做到哪了**」——随任务，结束即归档
- 两者不得混写。把系统规律写进 progress，或把任务进度写进知识库，都属于违反

## 体量约束（防上下文膨胀）

`progress.md` 每次会话开始都要读，是常驻成本，必须控制体量。

- **硬上限 150 行。** 超出即触发归档（见下「滚动归档」）
- **每次会话只读三节**：「当前状态」「下一步动作」「阻塞点」。其余按需展开，不默认全文读
- 这三节必须置于文件**最前**，且合计 ≤20 行

### 滚动归档规则

| 内容 | 保留策略 |
|---|---|
| 已验收的子任务 | 在「子任务进度」表中只留一行汇总（如「1~5 已验收，详见 progress_archive.md」） |
| 「本次会话变更」 | **只留最近 3 条**，更早的移入 `progress_archive.md` |
| 「已完成产物」 | 只留最近一轮；历史产物清单移入归档 |
| 「交接备注」 | 只留对**下一次会话**仍有效的内容；过期的直接删 |

归档动作在**会话结束更新时**顺手做，不单独开任务。

## 使用规则

1. 启用 XL 档时，把 `progress.md` 加入项目 `AGENTS.md` 的「必须先读」，并注明**只读前三节**
2. **每次会话开始**：读前三节，复述「上次做到哪、本次打算做什么」。需要细节时再展开其余章节
3. **每次会话结束前**：必须更新。未更新即结束，视为任务未交接
4. 每完成一个子任务，立即更新，不攒到最后
5. 更新时检查行数，超 150 行按滚动归档规则瘦身
6. 任务全部完成后：全文移入 `progress_archive.md`，`progress.md` 重置为空模板

复制下面代码块，另存为项目根目录的 `progress.md`：

```markdown
# 任务进度

任务卡：./tasks/<任务名>.md
规模档 / 干预档：XL / B
最后更新：YYYY-MM-DD　行数：<N>/150

<!-- 以下三节为每次会话开始的必读部分，合计 ≤20 行 -->

## 当前状态
<一句话：现在卡在哪 / 正在做哪个子任务>

## 下一步动作
<下次会话开始后第一件要做的事，具体到可直接执行>

## 阻塞点
- <阻塞内容>　等待：<人类回复 / 外部依赖 / 无>
- 关联问题：./pending_question.md 的 Q<序号>

<!-- 以下为按需展开部分，不默认读取 -->

## 子任务进度
| # | 子任务 | 状态 | 验收 | 完成日期 |
|---|--------|------|------|----------|
| 1 | | 已验收 | PASS | |
| 2 | | 进行中 | - | |
| 3 | | 待开始 | - | |

（已验收子任务超过 5 个时，合并为一行汇总并指向 progress_archive.md）

## 已完成产物
- <路径>：<说明>

（只留最近一轮）

## 本次会话变更
- YYYY-MM-DD：<做了什么、改了哪些文件>

（只留最近 3 条，更早的移入 progress_archive.md）

## 交接备注
<下一个会话（可能是另一个 AI 或另一个工具）必须知道的上下文；
只留对下次会话仍有效的内容；不要写系统规律——那属于 knowledge_base.md>
```

## 归档模板

任务完成后创建 `progress_archive.md`：

```markdown
# 进度归档

## <任务名>（YYYY-MM-DD ~ YYYY-MM-DD）
<把完成时的 progress.md 全文粘贴于此>
```
