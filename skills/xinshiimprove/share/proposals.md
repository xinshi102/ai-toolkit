# 规则修改提案

> **触发场景**：写规则提案、记试验结果｜**不用读的情况**：日常任务执行中｜**行数**：579

本文件是规则演进闭环的**第 ③~④ 环**（见 `governance.md` §规则演进闭环）。

## 写入规则

- **只追加，不修改、不删除**已有提案。状态字段可更新，正文不可改写
- 提案由 AI 根据 `observations.md` 撰写，**人类选择**哪个进入试验
- 提案阶段**不改任何规则文件**
- 编号 `R<三位数>` 连续递增，不复用
- 被否决的提案**保留**，防止同一想法被反复提出

## 状态流转

**常规路径**：`待选` →（人类选中）`试验中` →（有效）`已固化` →（实际使用验证）`已验证` ／（无效）`已否决`

**基础设施类快速路径**（见 `governance.md` §规则演进闭环 ④）：
`待选` →（人类选中）`已固化`（跳过试验）→（**下次实际使用后回填并由人类判定**）`已验证` ／（判据未达成）`已否决` + 回退

⚠️ 快速路径固化的提案**只能记「已固化」，不得直接记「已验证」**。
「已验证」必须有实际使用后回填的试验记录支撑。

## 提案 R005　闭环增设「基础设施类改动」快速路径

- 状态：**已固化**（待下次基础设施类改动时验证）
- 关联观察：O002、O004、O006
- 提出日期：2026-09-21
- 目标层级：L0（`governance.md` §规则演进闭环、§改动门槛 闸 3）
- 闸 0 频次：**同类观察 3 次 / 门槛 3 次（L0）—— 已达标** ✅

### 现状

`governance.md` §改动门槛 闸 3 要求：任何 L0~L2 改动须在项目内试验 ≥3 个任务、新规则被实际触发过、人类判定有效。
仅两种豁免：纯编辑性改动、删除类改动。

### 问题

自 v1.5 立此规以来，**连续三次** L0~L2 改动全部绕过闸 0 与闸 3：

| 观察 | 改动 | 绕过原因 |
|---|---|---|
| O002 | v1.6 三层加载 | 3 万 token 开销正在拖累每个任务，"用有问题的流程验证问题修复"形成循环 |
| O004 | v1.8 模板独立化 + M7 | 基础设施类改动，效果在"下一次用"时立刻可见 |
| O006 | v1.9 渐进式初始化 | 同上 |

共同特征：这三次改的都是**基础设施**（加载策略、文件组织、模板结构、提问清单），
其效果**不需要跑 3 个业务任务才能显现**——下一次使用该流程时立刻可判。
要求它们走"试验 3 个任务"是不可执行的要求（违反 M2 的精神）。

### 提议

闸 3 增加**第三种豁免**：

```markdown
- **基础设施类改动**：只改变规则库自身的组织方式（文件拆分/合并、加载策略、
  模板结构、提问清单顺序与数量），不新增对 AI 行为的约束。
  验证方式改为「下一次实际使用该流程时验收」，并在 proposals.md 中
  预先写明可判定的有效性判据（≥3 条，客观可判）。
  若下一次使用时判据未达成，按 §改动流程 回退。
```

同时在 §规则演进闭环 ④ 增加一句：基础设施类改动跳过项目内试验，但**必须在下一次使用后回填试验记录**，状态才能由「已固化」转为「已验证」。

### 影响范围

- 本库：`governance.md` §改动门槛 闸 3、§规则演进闭环 ④、CHANGELOG 必填字段（「试验记录」允许填"基础设施类，待下次使用验收"）
- 受影响的已接入项目：无

### 验证方式

- 试验项目：本规则本身即为 L0 改动，采用基础设施类快速路径（本提案定义的机制），下一次基础设施类改动时验证
- 有效判据：
  1. 下一次基础设施类改动能合法走完闭环，不再出现"绕过"记录
  2. 该改动在下一次实际使用后，试验记录被回填
  3. 若判据未达成能触发回退

### 试验记录

| 任务 | 日期 | 新规则是否被触发 | 现象 | 副作用 |
|---|---|---|---|---|
| | | 待下次基础设施类改动时触发验证 | | |

### 结论

人类当次指令「需要固化，开始做吧」——按 `collaboration.md` §裁决优先级 第 1 位执行。
本提案定义的即是"基础设施类快速路径"本身，按其自身规则：状态记「已固化」，**不直接记「已验证」**。

## 提案 R007　对外动作前必须由发起方校验前置条件（附闸门脚本骨架）

### 问题

2026-09-26：人类要求"启动 Codex 前必须确认网络出口在美区（否则有账号风险）"。AI 未校验地区即调用启动接口，被人类紧急叫停。同一环境里闸门此前只判"可达"不判"地区"，**静默放行**。

### 方案

§阶段定义与阶段门 增加一条：**对外动作（启动外部应用、对外发送请求、变更网络/代理设置）执行前，由发起方校验所声明的前置条件，全部通过才放行；不通过即拒绝并报告缺哪一条**（fail-closed）。附可复用闸门脚本骨架：

1. 确保依赖服务就绪（必要时启动，并等待其**运行时信号**出现）
2. 强制期望状态（模式 / 节点 / 端口），并等待异步生效
3. **实测**关键指标（不认标签、认实测），不达标则换候选重试，全不达标即拒绝
4. 全部通过才执行目标动作；**执行后复测一次**，仍不达标则自动回滚
5. 全程留痕到日志文件；提供 `--check` / `--close` / `--restore` 三个模式

- 闸 1：证据 = O009（未验地区即启动外部应用，被人类紧急叫停）
- 闸 2：低层解决不了——项目 `AGENTS.md` 只能约束本项目，而"对外动作"跨项目普遍存在
- 闸 3：未做试验
- 闸 4：净增长——可把"探针须显式带代理"这类环境细节下沉到 `tools/dsh.md`，正文只留义务条款

### 判据（若人类选择快速路径固化，供日后回填）

1. 此后每次对外动作前的报告里都出现"前置条件 + 实测值"

## 提案 R011　四问触发时机放宽 + 反频率约束

- 状态：**已固化**（人类当次下令，2026-10-10，CHANGELOG v1.13）
- 关联观察：O007（本提案是 R006 的效果回填——放宽"必答"之后，仍出现"每轮都问"的偏离）
- 提出日期：2026-10-10
- 目标层级：L1（`collaboration.md` §自评报告格式 第 10 项 + `ROUTER.md` 红线）
- 闸 0 频次：不适用（人类当次显式指令，沿用 R001~R010 的豁免口径）

### 现状

R006 固化后，两处条文写的是「**仅任务结束时**反问四问，一句话，没人认就不写台账」。

### 问题

2026-10-10 的插件恢复任务里，四问与台账草稿在**同一话题上连续三轮出现**：收尾问一次 → 未获回应又追问一次 → 再主动写出整份台账草稿。人类反馈：这成了"困扰我的枷锁，反而让我不愿意一直去沉淀这些东西"，要求"精简弹出的频率"。规则原文只写了"仅任务结束时"，没写"未回应怎么办""同一话题能否再问"，偏离时无条文可依。

### 方案

- 触发时机放宽为两个：① **任务收尾一次**；② **AI 判断确有必要时**（不得退化成每轮例行）。
- 补反频率约束：**同一话题只问一次**；**人类未回应即视为放弃，不得重复追问**；**未获认领不得自行写台账草稿**。

- 闸 0：不适用（人类当次显式指令）

- 闸 2：低层解决不了——触发时机写在 L1 的两处常驻条文里，项目/工具适配层管不到
- 闸 3：豁免（人类当次下令；语义收窄而非扩张）
- 闸 4：净增长——只改两处既有条文措辞，不新增文件、不复制内容

### 判据（回填用）

1. 下一次任务收尾只出现一句话反问，且**不逐条作答**
2. 人类未回应时，下一轮**不再重复**同一话题
3. 台账草稿只在人类明确认领后才出现
