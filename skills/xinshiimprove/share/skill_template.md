# 技能文件模板

> **触发场景**：新建技能文件时复制模板｜**不用读的情况**：只是使用已有技能｜**行数**：57

版本：v1.1
更新日期：2026-09-21
上位文件：`collaboration.md`

`share/skills/` 只沉淀**通用技能**：与具体项目无关、可被多个项目直接引用的方法与避坑经验。
只服务单个项目的知识，写进该项目的 `knowledge_base.md`，不要放这里。

技能文件不得重复 `collaboration.md` 的协作规则（阶段门、验收、未知处理等），只写本领域特有内容。
技能与协议冲突时，以协议为准（`collaboration.md` §裁决优先级）。

新建技能时，复制下面代码块，另存为 `share/skills/<技能名>.md`，逐节填写。标注「必填」的小节不得删除。

```markdown
# 技能：<技能名>

版本：v1.1
更新日期：YYYY-MM-DD

## 适用场景（必填）
<什么情况下该读这份技能，一到三条，具体到可判断>

## 不适用场景（必填）
<什么情况下不要用它，避免被误引用>

## 前置条件（必填）
- <需要的环境、权限、工具、已装软件>
- <需要人类先提供的信息>

## 核心步骤（必填）
1. <步骤>
2. <步骤>
（只写本领域动作，不写"先读 collaboration.md"这类通用流程）

## 已知坑（必填）
- 现象：<观察到什么>
  原因：<为什么>
  应对：<怎么办>

## 验收要点（必填）
- <本技能产物应如何验证；属可执行产物则给脚本要点，属文档产物则给 checklist 要点>

## 术语
- <本技能引入的专有名词及定义；无则写"无">

## 变更记录
- YYYY-MM-DD v1.0 创建
```

## 命名规范

- 文件名：全小写英文 + 下划线，`.md` 结尾（例：`verification_discipline.md`）
- 一个技能一个文件，不做子目录
- 文件名即技能名，项目 AGENTS.md 中按 `<SHARE_ROOT>/skills/<技能名>.md` 引用
