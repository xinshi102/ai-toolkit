# 技能：与外部应用/进程集成（external_app_integration）

> **触发场景**：需要改动或对接一个**别人写的**应用/服务（改它的配置、开它的窗口、替它转发、给它塞消息）｜**不用读的情况**：只跟自己项目内的代码打交道｜**行数**：81

版本：v1.0
更新日期：2026-09-26

来源：`dshworkspace` 生态任务 2026-09-24 ~ 09-26（DeepSeek ↔ Codex 协作桥验收 + Clash Verge 网络前置）。材料：该项目 `docs/codex-bridge-*.md`、`scripts/codex-gate.mjs`、`scripts/codex-port-shim.mjs`。

## 适用场景

- 要改第三方应用的配置文件、注册后台服务、写全局环境变量
- 要让两个进程/应用互通（转发端口、投递消息、共享状态）
- 要在启动某个应用**之前**施加前置条件（网络、权限、目录）

## 不适用场景

- 只改自己仓库内的代码与配置
- 纯读取第三方应用的状态（只读不涉及本技能的三条纪律）

## 前置条件

- 能观察该应用的**运行时**状态：控制接口、日志、进程、socket
- 明确知道"什么条件成立才允许动作"，说不出来的先问人类

## 核心步骤

### I1 不要相信它的配置文件——它会自己覆盖

第三方应用常把**自己的状态**当作唯一事实来源，启动时重写你手改的配置文件。

- 反例（真实发生，2026-09-26）：把 `startup_script` 写进 Clash Verge 的 `verge.yaml`，应用运行中编辑 → 退出时被回写成 `null`，改动**完全丢失且无任何报错**
- 执行要求，二选一：
  - **在应用未运行时**改配置，并**立刻重启应用验证**配置是否被保留；
  - 改**运行时状态**（控制接口/socket/API），并在应用每次启动后**重新施加**——用外部信号（如监视其 socket 出现）做触发器，别指望它读你的文件
- 判据：改动后必须有一次"重启应用 → 复查状态仍生效"的证据

### I2 用发现文件取代硬编码地址

跨进程/跨应用连接不要写死 `host:port`；端口是启动时决定的，写死必然过期。

- 反例（真实发生，2026-09-26）：协作窗口 App 把服务地址写死为 `http://127.0.0.1:3080/...`；宿主换代后端口变为 19387 → 窗口整片不可用，只显示"服务尚未就绪"，**没有任何线索指向端口**
- 执行要求：由**提供方**发布发现文件（如 `bridge-server.json`：`{host, port, pid, updatedAt}`），消费方启动时读取；提供方换端口即自动跟随
- 临时补丁（垫片/转发）只能算过渡，必须在交付报告里标注"待对方改为动态发现后即撤"

### I3 常驻改动必须登记且可一键撤销

在别人机器上留下的后台服务、全局配置、环境变量，属于**跨会话副作用**，不做登记就等于埋雷。

- 反例（真实发生，2026-09-26）：为让探针走代理写入 `~/.curlrc`；对方应用改用显式 `--proxy` 后该文件变成冗余，但**没人知道它还留着**，直到复跑校验才发现
- 执行要求：每装一样，登记四字段——**装了什么 / 装在哪 / 为什么 / 怎么撤**（撤销命令必须可复制执行），并在交付报告里列为独立小节
- 判据：交付报告里能一眼看到全部常驻改动与撤销方式；换代或对方修复后逐项复核是否仍需要

## 已知坑

- 现象：改了配置却毫无效果，也不报错
  原因：应用启动时用自己的状态覆盖了配置文件（见 I1）
  应对：改完必须重启验证；或改运行时状态
- 现象：接口"连不上"但目标服务明明在跑
  原因：地址/端口是硬编码的旧值（见 I2）
  应对：先找有没有发现文件，再怀疑网络
- 现象：换机器/换版本后出现"来历不明"的后台进程或代理设置
  原因：此前留的常驻改动没有登记（见 I3）
  应对：交付时强制登记；换代后逐项复核

## 验收要点

- [ ] 每个配置文件改动都附"重启后仍生效"的证据
- [ ] 跨进程连接用的是发现文件或运行时查询，不是硬编码地址
- [ ] 常驻改动有四字段登记（装了什么/在哪/为什么/怎么撤）
- [ ] 临时补丁已标注失效条件（何时可撤）

## 术语

- **发现文件**：由服务提供方写出的、含当前 `host/port/pid/时间戳` 的小文件，供消费方读取以替代硬编码。
- **常驻改动**：任务结束后仍留在机器上的副作用（后台服务、全局配置、环境变量、转发规则）。
- **垫片（shim）**：为兼容旧地址/旧协议临时加的转发层，应在对方修复后撤除。
