# 旧对话标准化协议

> **触发场景**：手上有一段没按协议跑的旧 AI 对话，要把它转成标准项目文件｜**不用读的情况**：项目已有 AGENTS.md（读 adopt_project.md）｜**行数**：142

版本：v1.1
更新日期：2026-09-21
上位文件：`collaboration.md`、`governance.md`
公共部分：`_project_common.md`（入口三选一 / 档位 / 方案确认门 / 接线模板 / 公共验收项 / 公共知识沉淀 / 公共边界）

本文件只写**本流程差异**，公共部分不重复。
入口三选一见 `_project_common.md` §入口三选一；档位见其 §档位。
本协议第 6 步结束后，仍需走 `adopt_project.md` 完成接线。

---

## 第 1 步：圈定材料与声明局限

**只读**，不写文件。

1. 列出材料来源：对话记录文件 / 导出文本 / 人类口述回忆，逐项给出体量（行数或轮次）
2. 标注**可信度**：
   - **有原文**：对话记录完整可查 → 可作为证据
   - **仅摘要**：只有片段或转述 → 标注"待确认"
   - **凭记忆**：人类口述，无原文 → 一律标注"人类口述，未验证"
3. 声明局限：**不得把回忆当事实**。无原文支撑的结论，置信度一律为"推测"

**红线**：本协议全程不得虚构对话中未出现的内容。拿不准的写"材料未覆盖"，不要补全。

---

## 第 2 步：四类提取

逐段过材料，把内容归入四类。**不属于任何一类的丢弃，不要硬塞。**

| 类别 | 特征 | 去向 |
|---|---|---|
| **A 目标与约束** | 要做什么、不能做什么、红线、环境前提 | `AGENTS.md` |
| **B 系统事实** | 这个系统是怎样的：状态、特征、规律、已确认失败 | `knowledge_base.md` |
| **C 任务进度** | 这件事做到哪了：已完成、待办、阻塞点 | `progress.md` 或任务卡 |
| **D 通用方法** | 换个项目也成立的方法与坑 | 候选技能，走 `distill.md` 的四个测试 |

**易错点**：
- B 与 C 不得混写（`collaboration.md` §知识库规则）。"待验证"属 C 不属 B
- D 类不要在本协议里直接沉淀技能，只标为候选；沉淀走 `new_skill.md`
- 对话中的**失败尝试**属 B（已确认失败），价值高于成功路径，不要丢

---

## 第 3 步：标注证据等级

每条提取出的内容，必须标注来源与等级：

| 等级 | 含义 | 置信度 |
|---|---|---|
| **原文** | 对话中有明确记录，可引用 | 已确认 |
| **推断** | 由对话内容合理推出，但未明说 | 推测 |
| **口述** | 人类回忆，无原文 | 推测 |
| **缺口** | 应该有但材料里找不到 | —— |

**缺口必须单独列出**，不得跳过。它们是第 5 步要问人类的问题。

---

## 第 4 步：输出提取方案，等确认

按 `_project_common.md` §方案确认门 输出，并额外附：

1. 材料清单与可信度分布（原文 / 摘要 / 口述 各占多少）
2. 四类提取结果，每类条目数
3. **证据等级统计**：原文 N 条、推断 N 条、口述 N 条
4. **缺口清单**：哪些必要信息材料里没有
5. D 类候选技能清单（只列，不沉淀）

---

## 第 5 步：补缺口

针对第 3 步的缺口清单，逐条问人类。**至少必须问清**：

1. 项目根目录与项目名
2. 是否存在不可逆操作（决定干预档）
3. 预算上限
4. 材料中标为"推断"的关键结论，是否属实
5. 对话中未完成的事项，哪些还要继续做

问不清的：写入 `pending_question.md`，**不猜**。

---

## 第 6 步：生成文件

按 `new_project.md` 第 2、6 步建目录，按 `agents_template.md` §AGENTS.md — 成熟版各节要求 与 `project_files_template.md` 建文件（**走成熟版，不走骨架版**），内容来自第 2 步的提取结果。

差异点：

- `AGENTS.md`「项目目标」「项目特有约束」填 A 类内容，每条注明证据等级
- `knowledge_base.md` 填 B 类，置信度按第 3 步等级映射：原文→已确认，推断/口述→推测
- C 类内容：进行中的任务 → 建任务卡；跨会话的 → 建 `progress.md`
- `AGENTS.md` 追加「材料来源」节，格式见 `_project_common.md` §接线 的模板末段

---

## 第 7 步：接线

按 `_project_common.md` §接线 执行。本协议不重复该流程。

## 第 8 步：验收

先逐条核对 `_project_common.md` §公共验收项，再核对本流程专有项：

```markdown
# 旧对话标准化专有验收项

- [ ] 四类提取完整，每条都有证据等级标注
- [ ] B 类与 C 类未混写（系统事实 vs 任务进度）
- [ ] 所有"推断""口述"等级的条目，置信度均为"推测"
- [ ] 缺口清单已全部向人类问过，未答的已写入 pending_question.md
- [ ] AGENTS.md 含「材料来源」节，列明证据等级分布
- [ ] 无虚构内容——每条结论可追溯到材料或人类回答
- [ ] D 类候选技能只列出未沉淀
```

按 `collaboration.md` §自评报告格式 输出报告，等人类确认。

## 第 9 步：知识沉淀

按 `_project_common.md` §公共知识沉淀 执行。额外：标准化过程本身若暴露规则问题，按 `collaboration.md` §自评报告格式 的「规则观察」项记录。

## 边界

除 `_project_common.md` §公共边界 外，本流程额外遵守：

- 不把人类回忆当作已确认事实
- 不在本协议中直接沉淀技能（只标候选）
- 不删除、不修改原始对话材料
- 缺口不得自行填补，必须问人类或写入 `pending_question.md`
